# Notion 회의록 → Linear 이슈

Notion에 작성된 회의록 페이지에서 액션 아이템만 추출해 Linear 이슈로 생성합니다.
두 개의 MCP 서버(Notion 읽기 → Linear 쓰기)를 하나의 워크플로우로 연결하는 Skill입니다.

## 언제 사용하나

- 회의가 끝난 뒤 회의록에 적어둔 할 일을 Linear로 옮길 때
- "@담당자 / 마감일" 형태로 정리된 액션 아이템을 일괄 이슈화할 때

## 사전 준비

`/mcp` 명령으로 두 서버가 모두 인증되어 있어야 합니다.

```
/mcp
> notion: connected
> linear: connected
```

## 실행 절차

사용자가 회의록 페이지를 지정하면(페이지 제목 또는 URL) 아래 순서대로 진행해줘.

### 1) 회의록 페이지 찾기 및 본문 로드

```
notion-search  → 지정된 제목/키워드로 회의록 페이지 검색
notion-fetch   → 찾은 페이지의 본문 전체를 가져온다
```

검색 결과가 여러 건이면 후보 목록을 보여주고 사용자에게 어느 페이지인지 확인받는다.

### 2) 액션 아이템 추출

본문에서 아래 패턴을 액션 아이템으로 식별한다.

- 체크박스 항목 (`[ ]`, `- [ ]`)
- "TODO", "액션", "할 일", "Action item" 으로 시작하거나 포함된 줄
- `@이름` 멘션이 포함된 줄
- 마감일 표현 (`5/16까지`, `다음 주`, `2026-05-20` 등)

각 항목을 다음 필드로 매핑한다.

| Linear 필드 | 소스 |
|-------------|------|
| `title` | 액션 내용을 한 줄로 요약 |
| `description` | 회의록 원문 맥락 + Notion 페이지 링크 |
| `assignee` | `@멘션`된 사람 — `list_users`로 이름 매칭 |
| `due date` | 본문의 날짜 표현을 절대 날짜로 변환 |

### 3) 추출 결과 확인 (Human-in-the-loop)

이슈를 생성하기 **전에** 추출 결과를 표로 보여주고 사용자 승인을 받는다.

```
| # | title | assignee | due | description 요약 |
|---|-------|----------|-----|------------------|
| 1 | 키워드 모니터링 알림 버그 수정 | 지훈 | 2026-05-16 | ... |
| 2 | 2월 리포트 양식 개편 | 수민 | 2026-05-21 | ... |
```

사용자가 항목을 빼거나 수정하면 반영한 뒤 다시 확인받는다.

### 4) Linear 이슈 생성

```
list_teams  → 대상 팀 확인 (팀이 여러 개면 사용자에게 선택받는다)
save_issue  → 승인된 액션 아이템을 이슈로 생성
```

assignee 매칭에 실패한 항목은 담당자 없이 생성하고, 어느 항목이 미매칭인지 사용자에게 알린다.

### 5) 회의록에 역링크 남기기

```
notion-create-comment → 회의록 페이지에 생성된 이슈 목록을 코멘트로 추가
```

예: `→ Linear 이슈 생성됨: COD-12, COD-13`

이렇게 양방향 추적성을 확보한다.

## 출력 형식

마지막에 생성 결과를 요약한다.

```
회의록: "5월 14일 스프린트 회의"
생성된 이슈: 2건
- COD-12  키워드 모니터링 알림 버그 수정  (지훈, ~5/16)
- COD-13  2월 리포트 양식 개편           (수민, ~5/21)
미매칭 담당자: 없음
회의록 코멘트: 추가 완료
```

## 주의

- 이슈 생성은 되돌리기 어려운 작업이므로 **3단계 사용자 승인을 반드시 거친다**.
- 액션 아이템이 하나도 없으면 이슈를 만들지 말고 그 사실만 보고한다.
- 날짜는 상대 표현(`다음 주`)을 오늘 날짜 기준 절대 날짜로 변환해 기록한다.
