# Workflow 실습

같은 Workflow 패턴(**순차 → 병렬 → 확인 포인트 → 작성**)을 두 가지 실습으로 경험합니다.

- **실습 ① — MOP 월간 리뷰**: 저장소에 포함된 로컬 데이터로 진행 (도메인 예시)
- **실습 ② — 비교 리서치 (범용)**: 도메인 지식·로컬 데이터 없이 누구나 따라 할 수 있는 웹 리서치 예시

둘 중 편한 것으로 시작하세요. MOP 광고를 모른다면 **실습 ②**부터 권장합니다.

---

## 실습 ① — MOP 월간 리뷰 (로컬 데이터)

`practice/` 폴더에서 5단계 Workflow를 직접 실행해봅니다.
순차 처리, 병렬 처리, 확인 포인트를 한 번에 체험합니다.

### 전체 흐름

```
1단계: 데이터 파악 (순차)
    └── data 폴더의 파일이 몇 개인지, 어떤 내용인지 파악

2단계: 채널별 분석 (병렬)
    ├── 검색광고 성과 분석
    └── 쇼핑광고 성과 분석

3단계: [확인 포인트] 분석 결과 검토 후 계속 진행 여부 결정

4단계: 보고서 작성 (순차)
    └── 분석 결과를 취합해 report-monthly.md 생성

5단계: 액션 아이템 도출
    └── 다음 달 즉시 실행할 3가지 제안
```

### 실행

`practice/` 에서 Claude를 시작합니다:

```bash
cd practice
claude
```

아래 프롬프트를 그대로 입력합니다:

```
다음 순서로 2월 MOP 광고 성과 리뷰를 진행해줘:

1단계: data 폴더에 어떤 파일이 있는지 먼저 파악해줘.

2단계: campaign-search.md와 campaign-shopping.md를 동시에 읽고
       각 채널의 잘 된 점과 문제점을 채널별로 정리해줘.

3단계: 분석 결과 요약을 나에게 먼저 보여주고, 계속 진행할지 확인해줘.

4단계: 확인 후 report-monthly.md 파일에 종합 보고서를 작성해줘.
       형식: 핵심 요약 / 우수 캠페인 / 개선 필요 캠페인 / 예산 제안

5단계: 다음 달에 바로 실행할 수 있는 액션 3가지를 보고서 하단에 추가해줘.
```

### 관찰 포인트

| 단계 | 확인할 것 |
|---|---|
| 1단계 | `Glob` 도구로 폴더 탐색 |
| 2단계 | `Read`가 2번 동시에 실행되는지 (Sub-Agent 병렬) |
| 3단계 | Claude가 스스로 멈추고 확인을 기다리는지 |
| 4단계 | `Write`로 `report-monthly.md` 생성 |
| 5단계 | 앞 단계 내용을 바탕으로 맥락 있는 제안이 나오는지 |

### 왜 단계를 나누는가?

"2월 광고 분석해서 보고서 만들어줘" 한 줄로도 요청할 수 있습니다.
하지만 단계를 명시하면:

- **3단계 확인 포인트**에서 방향이 맞는지 중간 점검 가능
- 분석과 작성이 분리되어 결과 품질이 높아짐
- 어느 단계에서 문제가 생겼는지 바로 파악 가능

## 실습 ② — 비교 리서치 (범용)

> MOP를 몰라도 따라 할 수 있는 범용 예제입니다. 똑같은 Workflow 패턴을 **웹 리서치**로 경험합니다. 미리 준비할 로컬 데이터가 없습니다.

### 시나리오

"고민 중인 선택지 3개를 비교해 추천받기" — 여행지, 노트 앱, 노트북, 외주 업체 등 **무엇이든** 됩니다. 아래는 주말 여행지 비교 예시입니다.

### 전체 흐름

```
1단계: 비교 기준 정하기 (순차)
    └── 후보 3곳과 평가 기준을 확정 (Claude가 먼저 제안)

2단계: 후보별 조사 (병렬)
    ├── 후보 A 웹 리서치
    ├── 후보 B 웹 리서치
    └── 후보 C 웹 리서치

3단계: [확인 포인트] 조사 요약을 보여주고 계속 진행 여부 결정

4단계: 비교표 작성 (순차)
    └── compare.md 에 기준별 비교표 생성

5단계: 추천 도출
    └── 한 곳을 추천 + 그 이유 3가지
```

### 실행

빈 폴더에서 Claude를 시작합니다:

```bash
mkdir compare-research && cd compare-research
claude
```

아래 프롬프트를 입력합니다 (후보·주제는 원하는 대로 바꾸세요):

```
다음 순서로 "주말 여행지 비교"를 진행해줘. (후보 3곳: 강릉, 전주, 여수)

1단계: 비교 기준 3가지를 먼저 제안해줘 (예: 이동 편의 / 먹거리 / 볼거리).
       내가 기준을 확정하면 다음 단계로 가.

2단계: 세 도시를 동시에 웹으로 조사해서, 기준별 핵심 정보를 정리해줘.

3단계: 조사 요약을 먼저 보여주고, 비교표를 작성할지 나에게 확인해줘.

4단계: 확인 후 compare.md 파일에 기준별 비교표를 만들어줘.

5단계: 한 곳을 추천하고, 그 이유 3가지를 표 아래에 적어줘.
```

### 관찰 포인트

| 단계 | 확인할 것 |
|---|---|
| 1단계 | Claude가 기준을 먼저 제안하고 확정을 기다리는지 |
| 2단계 | `WebSearch`(또는 Sub-Agent)가 여러 번 동시에 도는지 — 병렬 |
| 3단계 | 작성 전에 스스로 멈추고 확인을 기다리는지 |
| 4단계 | `Write`로 `compare.md` 생성 |
| 5단계 | 앞의 조사 내용에 근거한 추천이 나오는지 |

> 💡 웹 접근이 어려운 환경이라면, 후보 정보를 직접 붙여넣고 2단계를 "붙여넣은 내용을 동시에 정리"로 바꿔도 같은 패턴을 연습할 수 있습니다.

### 응용 — 업무에 바로 쓰기

후보와 주제만 바꾸면 그대로 재사용됩니다.

- **도구 선정**: "노트 앱 3종(Notion / Obsidian / OneNote) 비교 후 추천"
- **장비 구매**: "노트북 3종 비교표 만들고 한 대 추천"
- **업체 검토**: "외주 업체 3곳 비교 후 장단점 정리"

핵심은 **순차(기준 확정) → 병렬(동시 조사) → 확인 포인트 → 작성**이라는 흐름이 주제와 무관하게 똑같이 작동한다는 점입니다.
